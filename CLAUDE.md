## Project Overview

A Vue 3 internal knowledge-base / blog application that renders Markdown articles and PDFs from the `public/articles/` directory. Navigation and routes are driven entirely by `public/links.txt` (a JSON file despite the `.txt` extension), which is fetched at runtime.

## Development Commands

- `npm run dev` — start dev server on port 3000 (auto-opens Chrome)
- `npm run build` — production build to `dist/`
- `npm run preview` — preview the production build locally

There are no lint or test scripts configured.

## Architecture

### Dynamic routing

Routes are **not** defined statically. On startup, `main.js` calls `loadDynamicRoutes()` before mounting the app. That function fetches `/links.txt`, then calls `router.addRoute()` for each entry, mapping `component` strings like `"MdViewer"` to actual Vue components via a dynamic import template literal (`../views/${link.component}.vue`). The `url` field is passed as a prop to the rendered component.

Static fallback routes (`/home`, `/about`, `/md-view`) are defined in `router/index.js` but are mostly unused.

### Navigation menu

`App.vue` loads `/links.txt` independently (via `fetch`) to populate the `el-menu` sidebar. Only `House` and `Document` Element Plus icons are registered in the `iconMap`; adding other icons requires updating that map.

### Content rendering

- **`MdViewer.vue`** — receives a `url` prop, fetches the Markdown file via axios, and passes raw text to `MarkdownPreview`.
- **`MarkdownPreview.vue`** — the core rendering component. Uses Options API (not Composition API). Renders via `markdown-it` with:
  - `highlight.js` (github-dark theme) for syntax highlighting
  - Custom `fence` renderer that intercepts `plantuml`/`puml` blocks (renders via `https://www.plantuml.com/plantuml/svg/…`) and `mermaid` blocks (client-side rendered with the `mermaid` library)
  - `markdown-it-front-matter` + `js-yaml` for YAML front matter parsing
  - ClipboardJS copy buttons injected into every `<pre><code>` block via `addCopyButton()` (must be manually destroyed in `beforeUnmount`)
  - TOC generated by scanning rendered DOM headings after `$nextTick`
- **`PdfViewer.vue`** + **`PdfPreview.vue`** — renders PDFs using `@vue-office/pdf`.

### Build / deployment

`vite.config.js` proxies `/api` → `http://localhost:8081` in dev. The production build is served by Nginx in Docker:

```
npm run build
docker build -t xiaozaoshu-nginx:latest .
```

`nginx.conf` uses `try_files … /index.html` for SPA routing and enables gzip.

## Article Management

`public/links.txt` is a JSON array. Each entry:

```json
{
  "name": "Sidebar display name",
  "path": "/route-path",
  "url": "/articles/FileName.md",
  "icon": "Document",
  "component": "MdViewer"
}
```

- `component` must match a filename in `src/views/` (without `.vue`). Currently only `MdViewer` and `PdfViewer` exist.
- `icon` must be a key in `App.vue`'s `iconMap` (`"House"` or `"Document"`).
- Place the article file in `public/articles/`. The app fetches it at runtime; no rebuild required.

## Key Quirks

- The navigation file is named `links.txt` but contains JSON — both `fetch` and axios treat it as text and parse it manually.
- `MarkdownPreview.vue` uses the Options API while most other components use Composition API (`<script setup>`).
- PlantUML diagrams depend on the external `www.plantuml.com` service; they will not render in air-gapped environments.
- The dev server `open` config hard-codes `'chrome'` — change to `true` if Chrome is not the default browser.
